# 爪Pro（Paw Pro）· 使用说明

键鼠自动化小工具，双击即用，不需要装 Python。

---

## 📌 本次更新（v36）

### 界面升级为「玻璃宝石」质感

参考了 GitHub 上多个成熟的玻璃拟态（glassmorphism）组件库与 CSS 配方，
把整套界面从「纯色面板 + 发光描边」升级为半透明磨砂玻璃 + 紫宝石按钮：

- **磨砂玻璃面板**：五个主面板（总览 / 鼠标区 / 键盘区 / 触发方式 / 宏区）、
  标题栏、右上角的配置浮层都改成半透明填充 + 背景磨砂，背后衬三团缓慢漂移的
  紫色极光，玻璃才有东西可「透」。
- **紫宝石主按钮**：顶面受光最亮、腰身本色、根部压深，配上下的棱线，
  转出来就是一块切好的紫水晶； hover 时辉光加强。
- **凹陷的输入槽**：所有输入框、下拉框改成比面板更深的半透明凹槽，
  与面板的「凸起受光」正好相反，层次一眼可读。
- **细节**：极淡的噪点层打散磨砂下的色带；按键帽、状态徽章、
  小统计块都补了受光棱线。

可读性没有为效果让路：玻璃层只是装饰，若系统设置开启「减少透明效果」，
会自动退回接近实色的面板；所有文字对比度维持原标准。
磨砂效果对性能开销较大，因此同屏玻璃面板数量是受控的，
低性能环境也可在设置里关闭「启动后自动隐藏成托盘」等无关项减负。

## 📌 上次更新（v35）

### 启停键改好后，退出重开不再回默认

以前无论把鼠标连点、键盘锁定或宏回放改成什么启停键，本次运行都能用，
但退出再启动后可能又变成默认的「鼠标中键 / F6 / F7」。

原因不是绑定失败，而是**绑定保存成功后，又被自动保存的表单覆盖了**：
绑定数据存放在 `trigger`，前端自动保存只提交鼠标参数、键盘参数和隐藏选项；
旧版把这份局部数据当成整份配置重写，几百毫秒后 `trigger` 就消失了。

v35 改为：先把局部改动合并进完整设置，再原子保存整份配置。现在会同时保留：

- 鼠标连点、键盘锁定、宏回放各自绑定的鼠标键；
- 三个区各自修改过的系统热键；
- 关闭到托盘等没有出现在本次表单里的设置。

启动恢复也补齐了宏区：保存值优先；若该键这次被其他程序占用，才临时回落到默认候选，
界面始终显示本次真正生效的键。

> 旧版已经擦掉的绑定无法从空配置里反推。安装 v35 后需要**重新绑定一次**；
> 从这次起，退出并重开仍会保留。

## 📌 更早更新（v34）

### 1. 修好了「回放时鼠标跑到左上角去点」

**这是本次唯一的严重 bug，之前宏回放基本不可用。**

现象：录好一段操作，点「开始回放」，鼠标不是去录的时候点的位置，
而是**跑到屏幕左上角 (0,0) 点一下**，任务当然完不成。

真因在底层注入的一行写法上：给系统发鼠标事件时要填坐标，字段名是 `dx / dy`，
代码里写成了 `x / y`。偏偏这种写法**不报错**——构造成功、发送也返回成功，
只是坐标一直是 0，于是每一步都把鼠标送到 (0,0)。

为什么以前没发现：**只有「需要搬动鼠标」的动作才会暴露**。
平时用「跟随光标」连点不需要搬鼠标，所以一直正常；
宏回放每一步都要先移动，一用就撞上。同样的写法还影响
「固定坐标」连点、鼠标抖器、拖拽——这次一起修了。

### 2. 宏区有了自己的启停键（默认 F7）

回放一启动，窗口就自动最小化把屏幕让给目标程序了。
以前想中途暂停，只能切回窗口点按钮——等于回放期间没法干预。

现在宏和鼠标区、键盘区一样有自己的启停键：

| 当前状态       | 按 F7 会发生什么                    |
| ---------- | ---------------------------- |
| 正在录制       | 结束录制（不用切回窗口点「停止录制」）        |
| 正在回放       | 暂停（动作定住，参数保留）               |
| 已暂停        | 继续（从刚才停的地方接着跑，不会快进）         |
| 空闲 · 已录好步骤 | 开始回放（用界面上设的倍速和次数）           |
| 空闲 · 什么都没有 | 提示「先录制」——不会按了没反应             |

几点说明：

- **它只管宏**。以前宏跟着鼠标区共用一个暂停开关，一按会把连点也定住；
  现在宏有自己的分区，互不干扰。全局 Pause 键仍然能一次冻住所有动作。
- **F7 被别的软件占了会自动降级**（Ctrl+F7 → F10），
  界面上显示的是**实际生效的那个键**，照着按就行。
- 想换成别的键：触发方式区 →「改系统热键」→ 下拉选「→ 宏启停热键」→ 按一下录入。
- 想用鼠标侧键（G1/G2）：触发方式区 → 下拉选「→ 启停宏回放」→「按下要绑的键」。

### 3. 界面换色：青色 → 紫色（跟图标一个色系）

程序名和图标早就换成「爪Pro · 紫爪」了，界面却还是一套青色——
任务栏里是紫爪，一开窗口是青蓝，像两个程序。这版把界面颜色统一到图标同一个色系。

**变的是什么**：强调色（按钮、高亮、辉光）从青色换成紫色，底色从带蓝味的黑换成带紫味的黑。
紫色不是随便挑的，是从图标本身取的——图标渐变的两端是 `#DEB0FF → #7A24D2`，界面取它的中段做主色。

**不变的是什么**：

| 项目 | 状态 |
| --- | --- |
| 布局（三栏 / 宽屏四栏） | 不变 |
| 切角形状、等宽数字字体 | 不变 |
| 状态颜色语义：薄荷=运行 / 琥珀=暂停 / 红=警报 | 不变，看颜色就知道状态 |
| 通知弹窗 | 同源换色，风格不变 |

所有按钮位置、文字、用法和以前完全一样，只是换了一件颜色配套的衣服。

### 4. 左上角小图标换成真爪子（v34 复核时补上）

窗口左上角原来那个小图案是一块**紫色切角方块**（界面自己画的装饰），
和任务栏的紫爪图标不是一回事。现在换成了和程序图标同款的
三根尖爪，颜色渐变也直接取自图标本体，一眼就能对上。

> 注意：这个修复在 03:16 之后打包的 exe 里。如果你手上这份是在此之前
> 双击打开还留在屏幕上的旧实例，关掉重开一次 `爪Pro.exe` 就是新版。

## 📌 更早更新（v33）

**只修图标，功能一行没改。**

### 1. 列表里的小图标跟大图标终于长得一样了

v32 换图标时，只有 256 那张是完整设计，16 / 24 / 32 三档是把 256 硬缩出来的。
母版顶端的紫色高光接近纯白，缩到 16 像素时细尖角整片糊掉，只剩三条发白的竖条——
所以任务栏、详细信息列表里那个小图标，看着像「另一个图标」。

这次把小尺寸重画了一遍：形状剪影保留，颜色换成饱和紫渐变，去掉过曝高光。
现在 16 / 24 / 32 / 48 / 64 / 128 / 256 七档都是同一只爪，缩到多小都能认出来。

### 2. 交付文件夹里其它 exe 不再是默认图标

之前只有图形版 `爪Pro.exe` 设了图标，另外 6 个 exe（命令行版、长按锁定两个版本、
三个诊断工具）用的还是打包工具自带的「黄文件夹 + 软盘」默认图标。现在统一换成爪Pro 图标。

### 3. 换完图标看不见变化？刷一下图标缓存

Windows 会缓存 exe 图标，同名文件覆盖后资源管理器不一定立刻重画。任选一种：

- 资源管理器里按 `F5` 刷新；
- 或者按 `Win+R` 输入 `ie4uinit.exe -show` 回车（重建图标缓存，几秒，不动任何文件）；
- 还是老图标就 `Ctrl+Shift+Esc` 打开任务管理器 → 找到「Windows 资源管理器」→ 右键「重新启动」。

## 📌 更早更新（v31）

**改名 + 界面精简 + 窗口终于能拖能缩。**

### 1. 程序改名为「爪Pro」（Paw Pro)

功能早就超出「连点」和「长按锁定」了，名字不再对得上。  
从这一版起，图形版 exe 叫 `爪Pro.exe`，窗口标题、托盘提示、配置文件、日志里都换成新名。  
宏文件格式没变，**v30 及以前存的宏直接能用**；配置导出文件名变成 `爪Pro配置-时间.json`。

### 2. 界面去掉大段说明文字

原来主界面有一整块「功能说明」，占掉将近一屏，真正要点的东西反而要往下滚。  
现在压成一行流程提示：`① 选触发方式 → ② 设参数 → ③ 启动`，其余说明留在本文件里。

按钮也统一了：主按钮、次按钮、卡片里的小按钮现在是同一个高度（34px）、同一个切角、同一套字号字距。  
以前三种尺寸混在一起，看着像三个不同软件拼的。

### 3. 窗口现在能拖动、能缩放

这是长期存在的老毛病，原因是**无边框窗口**：系统判断「点在标题栏 / 点在边框」时要看窗口的非客户区，  
而无边框窗口这块区域被压成 0 像素，系统直接认为「你点的是客户区」，于是拖动和缩放全都不接管。  
改法是不再依赖系统，自己算坐标再设窗口位置。

| 操作        | 怎么做                |
| --------- | ------------------ |
| 移动窗口      | 按住顶部标题栏任意位置拖动（按住 4 像素后才开始跟手，避免误触） |
| 改大小       | 拖四边或四角；鼠标移到边缘会变成双向箭头 |
| 最大 / 最小尺寸 | 最小 900 × 620，再往里拖会停住 |

拖边框时窗口内容会有轻微重排卡顿，松手即正常——这是实时改尺寸的正常现象。

### 补充：这一版打包名变了，旧文件别删

`交付/爪Pro.exe` 是新版；`交付/连点锁定器.exe` 停在 v30，留作回滚；  
`交付/连点锁定器-v5.exe` 是更早的备份，也不要删。

## 📌 更早更新（v30）

三件事：**录制能定起点、录完每一步都能改、最大化后短栏不再一大片空白**，  
外加修掉「最近按键」只偶尔闪一下的显示问题。

### 1. 「最近按键」以前只偶尔显示一次，现在会留 10 秒

原因：界面 500ms 才读一次状态，而一次点击从按下到抬起只有几十毫秒，  
采样刚好错过就显示「—」；以前抬起还会立刻把记录清空，所以几乎永远抓不到。

现在分两种显示：

| 状态       | 显示                   |
| -------- | -------------------- |
| 正按着      | `中键` / `G1`          |
| 刚按过、已经松开 | `G1（0.4 秒前）`，保留 10 秒 |

按侧键没反应时先看这一栏：**按了却一直是「—」，说明系统根本没把侧键当鼠标键上报**，  
按下面三条排查：换有线 / 2.4G → 驱动里设成「鼠标按键 4/5」→ 先用中键做对照。

### 2. 最大化后键盘区 / 触发方式区底部不再一大片空白

三栏仍然等高、底边齐平，但状态行和自检条改成了「页脚」——贴在卡片底部，  
空白从「卡片下方一块死白」变成「内容与页脚之间的间距」。

### 3. 录制有了起点：第一次点击才开始

以前点「开始录制」就立刻记账，从窗口切到目标程序路上那几下点击、  
鼠标移动全被录进去，回放时先在屏幕上乱点两下才进入正题。

现在「① 录制」里有起点下拉：

| 起点         | 什么时候开始记                  | 适合         |
| ---------- | ------------------------ | ---------- |
| 首次点击开始（默认） | 你在目标程序里按下的第一下鼠标键，就是第 0 步 | 绝大多数场景     |
| 3 秒后开始     | 倒数 3 秒，给你切窗口的时间          | 要先摆好鼠标位置   |
| 立即开始       | 点按钮就记（老行为）               | 脚本 / 连点类录制 |

起点之前只丢「鼠标移动 / 滚轮 / 键盘」，**第一次点击本身会留下来**，  
所以回放时第一下点在哪里，和你录的时候一模一样。  
等了 30 秒还没点，会自动取消录制并提示原因。

### 4. 录完自动变成「步骤」，每一步都能改

录完不再是一堆原始事件，而是**一行一个节点**：

```
0  点击 · 左键 · (789, 2444)        1427ms
1  点击 · 左键 · (812, 2501)        3081ms
2  按键 · W                         2059~2400ms
```

点任意一行打开「节点设置」：

| 能改什么              | 说明                               |
| ----------------- | -------------------------------- |
| 节点名称              | 例如把「点击」改成「领奖励」                   |
| X 轴 / Y 轴         | 想换落点直接改数字（只有点击 / 按住 / 移动有这一项）    |
| 延时类型              | 固定延时 / 随机延时（随机 = 区间内每次不同，更像人手）   |
| 延时                | **这一步做完后等多久再做下一步**，1000 毫秒 = 1 秒 |
| 执行完成后             | 执行下一步 / 结束宏                      |
| 删除 / 复制 / 上移 / 下移 | 调顺序、删掉误录的动作                      |

底部还有「＋ 插入等待」——两步之间想插一段停顿，不用重录。

鼠标轨迹默认不占步骤（否则录 10 秒能有几百条，根本没法编辑）；  
画图、走位这类需要轨迹的操作，说一声再加开关。

**回放吃的是改后的步骤**，不是录制时的原始数据——改了立刻生效。

### 顺手说清楚的两条

- 宏文件升级到新格式（多存了 steps）。**用 v29 及以前的 exe 打不开新宏**，  
  会明确提示版本不兼容（不会静默拿旧数据去乱点）。旧宏在新版里照常能打开，自动转成步骤。
- 录制 / 回放进行中不能编辑步骤（回放器正在读同一份数据），会直接提示。

## 📌 更早更新（v29）

**「按下要绑的键」现在 8 秒超时**，超时会直接告诉你下一步查什么。

以前点了「按下要绑的键」就一直挂着等，按侧键没反应时你只能干等；  
更麻烦的是这时随手点一下界面，左键就被当成触发键录进去，  
弹出「左键不能用作触发键」，看着像「侧键被识别成了左键」。

现在的行为：

| 情况          | 界面表现                                          |
| ----------- | --------------------------------------------- |
| 8 秒内按下中键/侧键 | 照旧：立刻绑定并显示「已绑定 侧键2(G2) → 鼠标连点」                |
| 8 秒没有任何按键   | 自动取消等待，红字提示**没收到任何标准鼠标键，请检查鼠标模式/驱动**，并给出三条检查项 |
| 按下左键/右键     | 提示改成「多半是你自己点界面时被录进来了…不要再碰左键」                  |

超时提示里的三条检查项：

1. 优先用**有线或 2.4G**——蓝牙模式下不少鼠标把侧键报成键盘/多媒体事件，程序收不到；
2. 到官方驱动里把侧键设成「**鼠标按键 4/5**」，不要设成键盘按键或宏；
3. 先试**中键**：中键能绑，就说明链路是通的，问题只在侧键上报。

另外修了自检条的一个显示问题：**「最近按键」以前对 G1/G2 不刷新**  
（只有 G3 以上会变），按了侧键自检条却一直显示「—」，排查时很容易误判。  
现在中键、G1、G2 都会实时显示。

「开始识别 / 完成添加」那条链路的时间口径也统一成 8 秒（以前界面上写着 5 秒、3 秒各一套）。

## 📌 更早更新（v28）

**修一个会把回放卡死的问题：录制结束用的 Pause 键，同时是全局暂停键。**

v27 的现象是「录完一段，点开始回放，窗口缩下去了，然后什么都没发生」——  
原因是按 Pause 结束录制时，这颗键顺带把**全局暂停**打开了，  
回放第一步就停在暂停门闩上，一个动作都不走。

现在的规矩：

| 场景   | 按 Pause 的结果                |
| ---- | -------------------------- |
| 正在录制 | **只结束录制**，不改暂停状态（录完可以直接回放） |
| 没在录制 | 照旧：全局暂停 / 恢复               |

另外两处一起补齐：

- **暂停中不允许起回放**：点「开始回放」会直接提示「先按 Pause 恢复」，  
  不再让你对着一个不动的窗口猜是不是坏了。
- **暂停热键降级到 ScrollLock 的机器，ScrollLock 也能结束录制**  
  （以前只认 Pause，那颗键被别的软件占了就按不动，只能切回窗口点按钮）。

## 附：宏录制区说明（v27 新增）

**新增「宏录制区」**：把一串键鼠操作录下来，之后一键按原时序重放。  
界面最下面多了一个独立分区（不占用上面三个区的宽度）。

### 四格怎么用

| 格         | 干什么                                                                        |
| --------- | -------------------------------------------------------------------------- |
| ① 录制      | 选起点（默认「首次点击开始」）→ 点「开始录制」→ 窗口自动最小化 → 在目标程序点一下作为起点 → 照平常操作 → **按 Pause 键结束** |
| ② 步骤      | 一行一个节点（点击 / 按键 / 滚轮 / 等待），点一行就能改名称、坐标、延时；可删除 / 复制 / 上下移 / 插入等待             |
| ③ 回放      | 选倍速（0.5x～4x）和次数，点「开始回放」；中途按 Pause 是**暂停**，点「停止回放」才结束                       |
| ④ 保存 / 载入 | 起个名字存下来，下次在「载入」里选回来直接用（改过的步骤一起存）                                           |

一句话流程：**① 录 → ② 改 → ④ 存 → ③ 放**。

### 三条要知道的规矩

- **录制时窗口是最小化的**，这是为了让目标程序拿到前台（和连点一样）。  
  按 Pause 结束后窗口会自动跳回来；不想按 Pause 也可以切回来点「停止录制」。
- **宏按绝对坐标回放**：录的是「点在屏幕上的哪个点」，不是「相对移动多少」。  
  所以换分辨率、窗口搬家、换显示器之后，同一份宏可能点偏。  
  靠鼠标相对位移控制的场景（比如 FPS 转视角）不适合用宏。
- **上限**：单个宏最多 2 万步 / 10 分钟，超了会自动停止录制并提示。  
  鼠标移动做了抽样（12ms / 4px），不会因为甩一下鼠标就录出几千条。

### 「忽略程序注入的按键」这个勾选框

默认**勾上**：任何程序用 SendInput 之类注入的按键都不会被录进来  
（包括本程序自己的连点/锁定）。这样录出来的宏只含你亲手做的操作。

什么时候要**取消勾选**：用远程桌面、屏幕键盘、部分触控板驱动时，  
那些输入在系统眼里也是「注入」，勾着就一条都录不到。录出来是空的就把它取消。

### 宏存在哪

- 存在**设置文件同目录的 `macros/`** 下，一个宏一个 `.json`；
- 和「方案」（`profiles/`）是**两套**：方案存的是连点/锁定的参数，宏存的是动作序列。  
  宏动辄上百 KB，混进方案文件会让每次改参数都重写一遍大盘，界面会卡。

### 用之前先确认这件事

宏的录制和回放都要**往目标程序注入**。如果目标程序是以管理员身份运行的  
（很多游戏、部分工具软件），本程序也**必须以管理员身份运行**，  
否则注入会被系统静默拦掉——现象是「显示已录制/已回放，但目标程序毫无反应」。  
本项目的老规矩：**右键 exe → 以管理员身份运行**，不要双击。

## 📌 更早更新（v26）

**点击位置多了两种：多点轮询、框内随机**（原来只能「跟随光标」或「一个固定点」）。

| 位置模式     | 干什么              | 典型场景              |
| -------- | ---------------- | ----------------- |
| 跟随光标     | 鼠标在哪就点哪（老行为）     | 手动走位、点对话          |
| 固定坐标     | 每一下都点在同一个点       | 站在一个采集点反复采        |
| **多点轮询** | 依次点 A→B→C→A… 循环  | 多个采集点/多个按钮轮流点     |
| **框内随机** | 每一下在两点围成的矩形里随机取点 | 不想每次都点同一个像素（更像人手） |

怎么用：

1. 位置下拉选「多点轮询」或「框内随机」，下面会多出一个**坐标列表**框；
2. 把鼠标移到目标点，点「追加当前坐标」——按一次加一行，录几个点就点几次；  
   （也可以直接在框里手输，每行一个 `x,y`，或一行写完用 `;` 隔开）
3. 点 ①「就绪」→ 按触发键开始。

两个模式的规矩：

- **多点轮询**：至少 2 个点，按列表顺序轮流取，到最后一个回到第一个。  
  第 N 下点的是列表第 `(N-1) % 点数 + 1` 个 —— 次数用完前可以自己算。
- **框内随机**：正好 2 个点（左上、右下），两个点**倒着录也行**，程序会自己排正。
- 录错了点「清空」重来；列表存进设置文件，重启还在。
- 点数上限 200 个。某一行写坏了会整条报错、不会静默丢掉那一行  
  —— 少点一个位置比报错危险得多（挂机时没人盯着）。

> 命令行（`鼠标连点器.exe --profile`）只支持「跟随光标 / 固定坐标」。  
> 用到多点轮询或框内随机的方案在命令行里运行会**明确报错并退出**，  
> 不会偷偷退化成「跟随光标」跑到错误的地方去点。

**顺带修好一个静默 bug**：命令行 `--mode fixed --pos x,y` 以前根本没生效  
（程序算了坐标却从没把鼠标搬过去，实际点在当前光标位置）。现在会先搬再点。

## 📌 更早更新（v25）

**副屏坐标修好了**（原来固定坐标只认主屏）。

以前的限制：固定坐标按**主屏**像素算，鼠标只能落在主屏范围内。副屏在主屏**左边**  
（坐标是负数）或右侧时，手输/「取当前」录的副屏坐标会被夹到 0 或主屏边缘——  
表现就是「一启动，鼠标飞到左上角」。

现在的行为：

| 场景           | 以前              | 现在               |
| ------------ | --------------- | ---------------- |
| 单显示器         | 正常              | 正常（换算结果完全没变，零风险） |
| 副屏在主屏右侧      | 坐标被夹到主屏边缘       | 正确落在副屏           |
| 副屏在主屏左侧（负坐标） | 负坐标被夹成 0 → 飞左上角 | 负坐标正常生效          |
| 副屏在主屏上方（负 Y） | 同上              | 正常               |

连带的好处：循环拖拽、动作宏、抖器的「固定坐标起点」也一起支持副屏了——  
它们走的是同一套坐标换算。

> 本机只有一块屏，副屏这条路是用打桩测试验证的（几何换算三组场景 + 事件标志位）。  
> 插上副屏后建议这样验一次：固定坐标点「取当前」录下副屏上的某个点 →  
> ① 就绪 → 触发，看点击是否落在那个点上。

## 📌 更早更新（v23）

三个新功能，都是挂机场景用得上的小件：**刷完自动收尾**、**命令行一键开刷**、**鼠标抖器**。

### 1. 完成后动作（刷完自动响铃 / 锁屏 / 关机）

鼠标区新增一行「完成后动作」，可选：不动作 / 提示音 / 锁屏 / 关机。

- **只有「自然完成」才触发**——次数用完、时长跑满才算。您主动点「停止鼠标」、  
  或中途出错，**都不会**执行动作（防止手停一下就被关机）
- 执行前有 **30 秒倒计时**，倒计时就显示在鼠标区状态行上；这期间：
  - 回仪表盘点「取消收尾」→ 立即放弃
  - 点「停止鼠标」或按触发键停下 → 同样放弃
- 关机是双保险的：我们数完 30 秒后发的是**延迟 60 秒**的系统关机指令，  
  即使在别处把它当成「程序卡死」杀掉，也还有 60 秒在命令行敲 `shutdown /a` 救回来
- 抖器（第 3 条）也支持这个：挪够次数后收尾

> ⚠ 挂机前请先小次数试一次（比如 5 次 + 提示音），确认动作和时机都对，再上大次数

### 2. 命令行按方案开刷（`--profile`）

图形界面里调好的参数可以用齿轮面板「存为方案」，命令行版现在能直接读它，  
**不开窗口、不点按钮，敲一条命令就按方案开始刷**：

```bat
鼠标连点器.exe --list-profiles           :: 看有哪些方案、方案存在哪个目录
鼠标连点器.exe --profile 挂机刷材料       :: 按这个方案无头开刷
鼠标连点器.exe --profile 挂机刷材料 --cps 20   :: 方案打底，个别参数临时改
```

- 方案目录就是 exe 同目录的 `profiles\`（写不进去时才退 `%LOCALAPPDATA%\MouseAutoClicker\`），  
  `--list-profiles` 会把真实路径打出来
- **方案名不存在、文件损坏、版本比程序新 → 直接报错退出**，绝不会「悄悄地按默认参数开点」。  
  挂错参数刷错东西比打不开严重得多，所以这里一律大声报错
- 把命令写进 `.bat` 双击启动，或配 Windows 计划任务定时开刷都行

### 3. 鼠标抖器（只挪不点，防息屏 / 防挂机检测）

「动作」下拉新增「抖器」：每隔几秒把鼠标挪动 1 像素再挪回来，**一次都不点**。

- 用途：远程会议中保持在线、防息屏、防某些平台的「长时间无操作」判定
- 和连点器共用同一套参数：次数上限（按「挪了几次」算）/ 时长 / 间隔浮动 / 固定坐标  
  （固定坐标 = 先搬到那个点，再绕着它抖）/ 暂停 / 停止，全都能用
- 状态行的「已注入次数」会一直是 0 —— 这是**对的**，它只挪不点
- 命令行也能用：交互菜单选 `5 = 鼠标抖器`，或 `--mode jiggler`

### 三个功能都会记住

收尾动作、抖器间隔都会存进界面设置，关掉重开不丢，也能随方案导入导出。

## 📌 更早更新（v22）

鼠标区新增四个进阶参数——参考了 GitHub 上多个同类开源程序  
（EC-Autoclicker、WinAutoClick、OP Auto Clicker 等）后补上的标配能力。  
**程序底层早就支持这些，只是以前的界面里没有**，这次全部接了出来。

| 新参数           | 干什么用                                      | 建议场景                                         |
| ------------- | ----------------------------------------- | -------------------------------------------- |
| **间隔浮动（±ms）** | 每轮点击的间隔在设定值上下随机浮动，节奏不再像节拍器一样准             | 游戏里挂机/连点：固定节奏容易被识别成脚本，浮动后接近真人手速              |
| **双击 / 三击**   | 「动作」下拉新增：每轮点 2 下或 3 下                     | 需要双击打开/三连击触发的场合。注意「点击次数」按**轮次**算（一轮 = 2/3 下） |
| **固定坐标**      | 「点击位置」选固定坐标后，每次都点在同一个点；配「取当前」按钮一键录入鼠标所在位置 | 挂在某个按钮上反复点（副本奖励、确定框），不用一直挪鼠标                 |
| **启动倒计时（秒）**  | 按触发键后先数几秒再真正开始，期间可以暂停（停表）或停止（取消）          | 启动后需要几秒钟切到目标窗口的场合。长按模式不支持倒计时（界面会自动禁用）        |

几个要知道的细节：

- **间隔浮动和 CPS 的关系**：CPS 是平均值，浮动只在这个平均值上下抖，不会把速度改快
- **固定坐标按主屏坐标算**：多显示器的用户，如果目标窗口在副屏，手输坐标会偏——  
  「取当前」录的是鼠标真实位置，单显示器环境下直接可用
- **倒计时期间按触发键 = 暂停倒计时**（停表，不消耗秒数），再按一次继续数；  
  点「停止鼠标」直接取消
- 这四个参数都会记住（关掉重开不丢），也能随配置方案导入导出

两条实测问题的修复，都跟「暂停」和「方案」有关。

| # | 问题                    | 现象                             | 真因                                         | 现在                        |
| - | --------------------- | ------------------------------ | ------------------------------------------ | ------------------------- |
| 1 | 全局暂停/恢复按钮像卡死          | 鼠标区和键盘区都暂停时，点右上角「恢复运行」没有任何反应   | 暂停/恢复是「切换」动作，手快连点两下 = 切换两次 = 回到暂停态，看着像没反应  | 按钮加了 600ms 防抖：快速连点只认第一次   |
| 2 | 按 G1 恢复键盘区，鼠标区跟着恢复    | 鼠标区已暂停，按一下键盘区的触发键，暂停中的鼠标区也跑起来了 | 恢复单个区时，旧代码把两个区的暂停标志一起清掉了                   | 只清该动的：按 G1 只恢复键盘区，鼠标区保持暂停 |
| 3 | v19 存的方案加载报「没有可识别的参数」 | 调好参数「存为方案」，下次加载却提示配置为空         | 存盘时只写了文件、没更新程序内存，而导出方案读的是内存——全新启动时存出来的是个空壳 | 存盘即同步内存，存出来的方案带完整参数       |

### 关于第 1 条：暂停按钮的正确用法

右上角按钮是**一个开关**，不是「只恢复」：

- 两个区都暂停 → 点一下 → **全部恢复**
- 都在运行 → 点一下 → **全部暂停**

如果只想恢复其中一个区，用各自的触发键（鼠标区用中键/G2，键盘区用 G1），  
另一个区不受影响——这正是第 2 条修好的行为。

### 关于第 3 条：方案文件

方案存在 exe 同目录的 `profiles/` 文件夹，一个方案一个 `.json` 文件。  
v19 存出来的空壳方案（内容只有一行 `{"schema_version": 1}`）加载时仍会提示  
「没有可识别的参数」——删掉它，在界面调好参数后重新「存为方案」即可。

一个键盘区的行为修正，实测报回来的。

| 1 | 键盘区「就绪 → 长按 W 锁定 → 点暂停 → 再按 W」，会蹦出一句「已解除锁定」 | 暂停时**只把键松开了，没把锁定状态清掉**。系统里那个键仍被记着「锁定中」，所以你按 W 被当成「锁定中再按一次 = 解除指令」 | 已修复：**暂停 = 松手 + 解除锁定**，两件事同时做 |

### 键盘区的「暂停」到底做了什么

先说清楚：鼠标区的「暂停」是**动作定住、参数保留**——连点停下来，再按恢复，接着连。

键盘区不一样。它的本体就是「一个键被按住」，所以它的暂停只能是**松开**：

| 你的操作        | 发生什么                                             |
| ----------- | ------------------------------------------------ |
| 长按 W 到阈值    | 进入锁定，W 一直被按着                                     |
| 点一次触发键（暂停）  | **W 被松开，锁定解除**；通知写「键盘锁定 已暂停 · 已解除锁定 · 再按 X 恢复运行」 |
| 再点一次触发键（恢复） | 键盘区重新待命；通知写「已恢复运行 · 长按 W 可重新锁定」                  |
| 恢复后长按 W     | 按正常规则重新锁定（长按够阈值才锁）                               |

两个细节，都是顺手一起修掉的：

- **暂停期间按 W 是没反应的**（等于没按）。不这么改的话，「暂停时按住 W 不放，再去点恢复」会在恢复的一瞬间就把 W 锁上，你什么都没干角色就自己跑起来了。
- **暂停不会误伤**：暂停时 W 会被补一个「抬起」事件，所以游戏里角色一定会停下来，不会卡在「一直按着」。

> 全局暂停键（Pause）走的是同一套逻辑，按键时键盘区的锁定也会一并解除。

### 第 1 条：原神排查结论（2026-10-16 实测打通）

**结论先说：连点锁定器在原神里是可以用的**，鼠标连点（一直普攻）和键盘锁定（一直前进）都实测通过。前提就两条：

1. **必须以管理员身份运行**（右键 → 以管理员身份运行）。原神是管理员权限，Windows 的 UIPI 机制会**静默拦掉**普通权限程序发给高权限窗口的输入——不报错、不回失败，就是没反应。双击启动 ≠ 管理员启动，这是之前排查半个月的主因。
2. **启动后仪表盘自动最小化**（默认开启，可关）。`SendInput` 把事件发给当前前台窗口；仪表盘自己占着前台时，点击全点在自己身上。

**以后在任何游戏/软件里遇到「没反应」，30 秒定位法**（照顺序，每步有明确判据）：

| 步 | 做什么                    | 判据                                                        |
| - | ---------------------- | --------------------------------------------------------- |
| 1 | 看启动日志有没有「连点滴答：已注入 N 次」 | 有且 N 在涨 = 程序在发，往下查；没有 = 压根没启动，查热键降级和是否管理员                 |
| 2 | 记事本放前台跑一次              | 记事本也不行 = 程序问题；记事本行、目标不行 = 目标侧                             |
| 3 | 键盘锁定按下去，看能不能进游戏聊天框     | 能进聊天框但不触发动作 = 按得太短（本程序按下-抬起间隔 20ms，在安全区）；连聊天框都进不去 = 权限或焦点 |

日志位置：`%LOCALAPPDATA%\MouseAutoClicker\logs\launch.log`。

- 界面所有提示（就绪弹窗、状态条、卡片里的说明文字）显示的都是**实际注册成功的键**

### 第 2 条：鼠标为什么自己动 —— 是排查时的测试脚本，不是程序

**结论：程序内部没有任何会自动启动连点的逻辑**（只有你点「开始」才运行）。

真正的原因是我在上一轮排查绑键 bug 时，写了两个临时探针脚本，  
它们为了验证「系统会不会真的投递原始输入」，主动调用了 `SendInput`  
**向系统注入了一次鼠标中键的按下和抬起**。而你当时正在电脑前，  
于是就看到鼠标自己点了一下中键。同理，`regression_keyhold.py`  
结尾有一行「真的敲一个 W」，也会让键盘动一下。

这类测试会**污染你正在使用的真实输入环境**，属于不严谨的操作。  
已经加上闸门：

- 所有回归测试**默认不再向系统注入任何真实输入**；
- 端到端验证改成「直接把构造好的报文喂给解析函数」，  
  这样既不动你的键鼠，反而还多了个好处——  
  能自由构造按键位图，**把 G3~G8 也覆盖到**（走 SendInput 反而测不了，  
  因为合成输入的位图恒为 0）；
- 确实需要验证「系统真的会投递消息」时，显式加 `--real-input`，  
  脚本会先倒数 2 秒并打印醒目提示，不再"偷袭"。

**第 1 条为什么之前一直修不好**——失效原因不是一个，是五个叠在一起，  
而且**五个都不报错**（API 返回成功、异常被 `except: pass` 吞掉）：

| # | 错在哪                                               | 后果                                           |
| - | ------------------------------------------------- | -------------------------------------------- |
| 1 | `dwFlags` 写成 `0x01`，注释却写 RIDEV_INPUTSINK          | `0x01` 其实是 **RIDEV_REMOVE**，等于**反注册**，监听根本没开 |
| 2 | `hwndTarget = None`                               | 原始输入跟随**键盘焦点窗口**，我们自己的后台线程一条都收不到             |
| 3 | `GetRawInputData` 的 `uiCommand` 传了 `RIM_INPUT`(3) | 非法命令 → 返回 `(UINT)-1`                         |
| 4 | `GetRawInputData` 的 `pcbSize` 传整数 `128`           | 被当成内存地址 `0x80` → 同样返回 `-1`                   |
| 5 | `RAWMOUSE` 结构漏了 `usFlags` 字段                      | 后续字段整体错位 4 字节，按下标志读成恒 0                      |
|   |                                                   |                                              |

最阴险的是第 3、4 条：调用失败返回 `-1`，而 `-1` 转成无符号是  
`0xFFFFFFFF`，比任何结构都大，于是 `cnt >= sizeof(...)` **恒成立**，  
代码拿着一个从没被写入的全零缓冲区继续解析，解出来永远是  
「当前没有任何键按下」——**静默失效，一行错误都没有**。

界面底部新增了「监听 / 消息数 / 最近按键」自检条，  
按一下鼠标键看数字涨不涨，3 秒就能判断链路通不通。

## 一、`鼠标连点器.exe` —— 连点 / 拖拽 / 动作宏

### 最快上手

**双击运行**，程序会一步步问你参数，直接回答后回车即可（都有默认值）。  
第一次用建议就这么走，完全不用记命令。

```
选择模式 [1] : 1
每秒点击次数 CPS [10] : 20
持续多少秒（0=一直点）[10] : 30
```

也可以一行写完参数：

```
鼠标连点器.exe --cps 20 --duration 30
```

含义：以每秒 20 次的频率点击 30 秒。

### 常用参数

| 参数           | 含义                               | 例子                                            |
| ------------ | -------------------------------- | --------------------------------------------- |
| `--cps`      | 每秒点击次数（1~100）                    | `--cps 20`                                    |
| `--duration` | 持续多少秒，`0` = 不限                   | `--duration 60`                               |
| `--count`    | 点击总次数，`0` = 不限                   | `--count 100`                                 |
| `--jitter`   | 随机抖动毫秒，让节奏不那么机械                  | `--jitter 50`                                 |
| `--button`   | 用哪个键：`left` / `right` / `middle` | `--button right`                              |
| `--pos`      | 固定坐标 `x,y`                       | `--pos 800,450`                               |
| `--points`   | 拖拽路径                             | `--points "100,100 -> 400,300"`               |
| `--steps`    | 动作宏队列                            | `--steps "click;wait@300;move@600,400;click"` |
| `--repeat`   | 跑完不退出，停在菜单等指令                    | `--repeat`                                    |
| `--once`     | 跑完直接退出（老行为）                      | `--once`                                      |
| `--prepare`  | 每轮前的准备秒数，默认 3，回车可提前开始            | `--prepare 0`                                 |
| `--next-key` | 「再来一轮」的全局热键，默认 F9，`none` 关闭      | `--next-key f8`                               |

### 跑完不退出：输 1 再来一次（v11 起）

一轮跑完**不退出**，停在菜单上等你发话，参数原样保留：

```
--------------------------------------------------------
  本轮结束，等你发话（参数原样保留）：
    1 + 回车 = 再来一次
    2 + 回车 = 重新配置参数
    q + 回车 = 退出
  请选择 [1]：
```

- **双击运行**（一步步问答）：默认就是这个行为，跑完输 `1` 或直接回车就再跑一轮
- **带参数运行**：想停住等指令就加 `--repeat`
  ```
  鼠标连点器.exe --cps 20 --duration 30 --repeat
  ```
- **想回老行为**（跑完就退出）：加 `--once`
- 每轮开始前有 3 秒准备时间，用来把鼠标移到目标位置；  
  回车可以立即开始，不想等就加 `--prepare 0`
- 等待菜单时按 **F9** 可以直接开下一轮，不用切回这个黑窗口  
  （游戏在前台时很方便；F9 被别的软件占了就失效，照样能输 1）
- 暂停键 **Pause** 在轮次之间一直有效，暂停期间不会开始新一轮

### 点击次数：1 到无穷大

- 点 **1 次**：`--cps 10 --count 1`
- 点 **无穷大**：`--cps 10 --duration 0 --count 0`（两个都填 0，就是一直点下去，`Ctrl+C` 停）

### 三种模式

**普通连点**（默认）——在鼠标当前位置持续点

```
鼠标连点器.exe --cps 15 --duration 30
```

**固定坐标**——鼠标移到哪都不影响，永远点指定位置

```
鼠标连点器.exe --cps 10 --pos 800,450 --count 50
```

**循环拖拽**——在一串坐标点之间反复拖动，适合画线、拉框

```
鼠标连点器.exe --mode drag_loop --points "200,200 -> 600,400 -> 200,400" --duration 60
```

**动作宏**——把多步动作排成队列循环，最灵活

```
鼠标连点器.exe --mode macro --steps "move@300,300;click;wait@500;click;wheel@2" --duration 30
```

宏的动作语法：

| 动作                      | 含义                     |
| ----------------------- | ---------------------- |
| `click`                 | 点击当前鼠标位置               |
| `click@100,200`         | 先移动到 100,200 再点击       |
| `dclick`                | 双击                     |
| `rclick`                | 右键                     |
| `move@300,400`          | 只移动                    |
| `drag@100,100->400,400` | 从 100,100 拖到 400,400   |
| `wheel@3`               | 向上滚 3 格（`wheel@-2` 向下） |
| `wait@500`              | 等待 500 毫秒              |

用分号 `;` 分隔每一步。

### 其他命令


## 二、`鼠标连点器-长按锁定.exe` —— 长按后一直按着

### 效果

- **长按 `W` 键 2 秒** → 进入锁定，`W` 一直处于按下状态
- **物理松开鼠标手上的 W 键** → 不影响，`W` 依然按着
- **再次按 `W` 键** → 解除锁定，恢复正常
- **没设置的键（比如 `A`）** → 完全不受影响，正常输入

### 使用

双击运行，默认对 `W` 键生效。程序会一步步问你参数，直接回答回车即可：

```
鼠标连点器-长按锁定.exe
```

自定义生效的键和阈值时间：

```
鼠标连点器-长按锁定.exe --keys w --threshold 2
鼠标连点器-长按锁定.exe --keys w,a --threshold 1.5
鼠标连点器-长按锁定.exe --keys space --threshold 3 --hz 40
```

`--hz` 决定「刷字有多快」：默认 30 次/秒，接近 Windows 原生长按手感。  
觉得慢就调到 50~~60（更吃 CPU）；觉得太快就降到 15~~20。

| 参数            | 含义                     | 默认    |
| ------------- | ---------------------- | ----- |
| `--keys`      | 生效的键，多个用逗号分隔           | `w`   |
| `--threshold` | 长按多少秒后锁定               | `2`   |
| `--hz`        | 锁定后刷字频率（次/秒）           | `30`  |
| `--vk`        | 改用虚拟键码注入（默认是扫描码）       | 关     |
| `--panic`     | **紧急释放键**，见下方「键盘卡住怎么办」 | `f12` |
| `--list-keys` | 查看所有可用键名               | —     |

> ⚠️ **务必先看这条：`SendInput` 只把按键投递给「当前处于前台」的窗口。**
>
> 也就是说：锁定生效时，你要操作的那个程序（游戏、浏览器等）  
> 必须正处于前台激活状态，否则注入的按键会打到别的窗口去。  
> 这是 Windows 的机制，不是本程序的 bug。
>
> 正确用法：把目标程序点到前台 → 再长按锁定键。  
> 不确定时可看锁定程序的窗口显示的「注入统计」——  
> 数字在涨说明注入在发，但没看到效果那就是目标窗口不在前台。

支持的键：字母 A~~Z、数字 0~~9、F1~F24、Space、Enter、Esc、Tab、  
Backspace、Shift、Ctrl、Alt、方向键、Delete、Insert、CapsLock、NumLock。

### ⚠️ 键盘卡住怎么办（重要，必读）

**任何时候按 `F12` 就能强制解除全部锁定**，不需要管当前是什么状态，  
也不需要先关窗口。它会立刻把所有锁定的键释放出来，键盘恢复正常。

- 想换别的紧急键：`--panic esc`（用 Esc 释放）
- 紧急键**永远不会**被吞掉，按下就一定生效
- 紧急键如果和你设的目标键冲突（比如 `--keys w --panic w`），程序会自动改用 F12

退出方式（正常退出也会释放所有键，不会留下卡住状态）：

- 按 `Ctrl+C`
- 或直接关窗口

> 万一连 F12 都按不动（极端情况）：用任务管理器结束`鼠标连点器-长按锁定.exe` 进程，  
> 然后随便按几下 `W` 键和 `Ctrl` 键，Windows 会自动复位键盘状态。

## 四、可扩展功能：加新模式不用改界面

架构上，加新功能只要写一个插件文件。

> 📖 **要加「鼠标录制」这类大模块，先读 `交付/扩展开发指南.md`**——  
> 里面写了四层架构、插件的完整长相（照抄结构）、鼠标录制三块拆法  
> （录制器挂哪个钩子 / 回放怎么零代码复用宏插件 / 界面两条路选哪条）、  
> 三条防「源码改了 exe 没改」的闸门，以及测试打包速查。

把新的 `.py` 文件放进 **exe 同级的 `plugins_ext` 文件夹**，下次启动自动生效，  
不需要重新打包。示例：

```python
# plugins_ext/my_click.py
from core.engine import Plugin, Registry
from core import inputs

class MyClick(Plugin):
    name = "my_click"
    title = "我的模式"           # 界面上显示的名字
    description = "点两下然后等一秒"

    FIELD = [                     # 界面自动生成这些表单项
        {"key": "gap", "label": "间隔(ms)", "type": "int",
         "default": 1000, "min": 0, "max": 60000},
    ]

    def run(self, ctx):
        while not ctx.should_stop():
            inputs.click("left", count=2)
            ctx.clicked += 1
            ctx.tick_count += 1
            ctx.wait(ctx.options.get("gap", 1000) / 1000.0)
        return ctx.clicked

Registry.register(MyClick())
```

插件里可以用到的 `ctx` 接口：

| 成员                                 | 说明                 |
| ---------------------------------- | ------------------ |
| `ctx.should_stop()`                | 是否该停（手动停止 / 到达上限）  |
| `ctx.wait(秒)`                      | 可被中断的等待            |
| `ctx.elapsed()`                    | 已运行秒数              |
| `ctx.clicked`                      | 已执行次数（自己累加）        |
| `ctx.tick_count`                   | 动作轮次，**次数上限按它判定**  |
| `ctx.cursor_position()`            | 按模式返回要点的位置         |
| `ctx.options`                      | 用户在界面上填的值          |
| `ctx.state`                        | 插件自己的持久化状态         |
| `ctx.base_interval()`              | 本轮该等多久（已含 CPS 和抖动） |
| `inputs.click/move_to/drag/scroll` | 鼠标操作               |

把新插件加进 exe 需要两处改动：`plugins/__init__.py` 的 `BUILTIN_MODULES`  
加一行，以及 spec 的 `HIDDEN` 加一行。

## 长按锁定在「带反作弊的游戏」里无效——怎么判断卡在哪一层

实测现象（已复现）：记事本有效，原神无反应。  
用 `注入目标诊断.exe` 测原神窗口，结果：

| 项              | 实测值            |
| -------------- | -------------- |
| 目标窗口是否前台       | 是              |
| `SendInput` 返回 | 24/24 成功，错误码 0 |
| **系统层收到的键盘事件** | **0 个**        |

判读：事件**没进入系统**就被丢弃，不是目标程序收到后不理。  
这通常是 Windows UIPI（用户界面特权隔离）——低权限进程向  
高权限窗口注入输入时会被静默丢弃，而 `SendInput` 依然返回成功。

### 实测已确认：本机原神以管理员权限运行

用 `注入目标诊断.exe`（含权限对比）实测本机结果：

| 程序           | 完整性级别          | 说明                   |
| ------------ | -------------- | -------------------- |
| 注入工具         | RID=0x2000     | 中完整性（普通用户）           |
| 原神 pid=71132 | **RID=0x3000** | **高完整性（管理员）** ← 高于工具 |
| 记事本          | RID=0x2000     | 中完整性，和工具同级 → 注入成功    |

**这就是记事本成功、原神失败的直接原因**：  
Windows 的 UIPI（用户界面特权隔离）禁止低完整性进程向高完整性进程注入输入，  
丢弃是**静默的**，而 `SendInput` 依然返回成功。

### 应对顺序

先按「更早更新（v12）第 3 条」的**记事本验证法**确认注入链本身是通的  
（记事本里连点、长按 W 都正常），再按下述顺序处理游戏内的无效：

1. **以管理员身份运行**（本机已确认这就是原因）  
   右键 `鼠标连点器-长按锁定.exe` → 以管理员身份运行。  
   两边同为高完整性后，UIPI 不再拦截，注入即可生效。

   2.x 新版启动时会自动做权限预检，  
   检测到有更高权限的程序在运行就直接在控制台提示原因。
2. **管理员运行仍无效**，用 `注入目标诊断.exe` 复测：
   - 「系统层收到 0 个」→ 权限或安全桌面问题，  
     检查有没有开锁屏/UAC 弹窗、安全软件是否拦截键盘钩子
   - 「系统层收到 N 个且目标在前台」→ 系统已收到，是目标程序  
     **主动丢弃注入事件**。带反作弊的游戏会检查键盘钩子里的  
     `LLMHF_INJECTED` 标志，只接受真实硬件按键。  
     这种情况下模拟键盘这条路走不通，没有技术解法。

### 表现成「反复点击」而不是「一直按着」—— 已修复

用户实测反馈：锁定后游戏里表现为「反复点击 W」，  
而不是「一直按住 W 角色持续前进」。

**原因**：早期实现是**成对注入**——每次都注入「按下 + 抬起」。  
目标程序每次都看到完整的按下+抬起，于是判定为「多次点击」。

**关键认知：差别不在频率，而在有没有抬起。**

| 模式                 | 注入方式                                | 程序看到什么       | 表现     |
| ------------------ | ----------------------------------- | ------------ | ------ |
| **按住（默认）**         | 重复注入 keydown（约 30Hz），**永不注入 keyup** | 键一直没松，且有持续重复 | 角色持续移动 |
| 成对（`--click-mode`） | 反复注入按下+抬起                           | 连续点击多次       | 反复点击   |


**两个要点缺一不可**：

1. 锁定期间**绝不能出现 keyup**，否则变成「反复点击」
2. keydown 必须**重复注入**——只发一次时游戏不响应（角色不动），  
   因为真人按住时硬件会持续产生 keydown 重复，游戏靠这个判定为「按住」

### 状态显示 locked 但角色不动

已修复。之前只注入一次 keydown，游戏收不到持续重复事件就不响应。  
现改为按`--hz` 频率重复注入 keydown（仍不发 keyup）。  
若仍不动，可尝试调高频率：`--hz 50`。

**用法**：

```
鼠标连点器-长按锁定.exe --keys w --threshold 2      # 按住模式（默认）
鼠标连点器-长按锁定.exe --keys w --threshold 2 --click-mode   # 反复点击模式
```

新版启动时会在控制台打印「锁定行为」一行，确认当前是哪种模式。

### 「反复点击」选了却完全没效果 —— 已修复

用户实测反馈：键盘区锁定行为选「反复点击」，启动后按键没有任何反应。

**根因有两个，都很隐蔽**：

**1. 参数解析的边界隐患（界面版，已加固）**  
前端下拉框的 value 是字符串 `"false"`，Python 端需要  
`str(v).strip().lower() == "true"` 才能正确解析。

两个已加固的边界：

- 若直接写 `params.get("hold")` 拿到的是字符串，而**非空字符串在Python 里恒为 True**，  
  「反复点击」会被当成「一直按着」；
- 若传进来的是**空字符串**，单靠 `== "true"` 会解析成 `False`，  
  相当于用户明明选了「一直按着」却跑成了「反复点击」，而界面上没有任何提示。

现在统一按 `str → strip → lower` 处理，且**空值显式回退为「一直按着」**（默认档）。  
字符串与布尔共 6 种取值均已实测通过。

**2. 按下与抬起之间零间隔（核心根因）**  
早期成对模式是两个注入调用背靠背执行：

```python
send_key(vk, up=False, ...)   # down
send_key(vk, up=True, ...)    # up   ← 间隔约 0.03 毫秒
```

两条事件几乎同时到达。目标程序的典型判定模型是：  
`keydown` 记状态 → `keyup` 时**在那个状态下**执行一次动作。  
零间隔时 `keyup` 到达时按键状态已经被改过，很多程序还会要求  
「按下持续 ≥10ms」才算一次有效点击，于是**整组被当成抖动丢弃**。

**表现为「反复点击」完全无效，而「一直按着」正常**——  
因为按住模式根本不注入 keyup，绕开了这个判定。

**修复**：成对模式按下后先等待再抬起，实测间隔 **20.3ms**（修复前 0.03ms）。  
新增参数 `--pair-gap` / 界面上的「按下时长(毫秒)」，建议 **15~40**。

**为什么之前的回归测试没抓到**：旧断言只数 `down=36 / up=36` 的**数量**，  
数量是配对的，看起来完全正常。必须量**时间差**才能发现。  
现已把断言改成「down→up 间隔 ≥10ms」，并新增一个模拟目标程序判定的用例  
（按下不足 10ms 不计数），实测 1.2 秒内从 0 次变成 10 次有效点击。

### 鼠标连点启动了但没法点目标界面 —— 已解决

用户反馈：点「① 就绪」后按 F5，仪表盘还在最前面，没法去点目标程序。

**原因**：`SendInput` 把事件发给**当前前台窗口**。  
靠点按钮启动时仪表盘自己就是前台，连点全点在自己身上。

**解决**：

1. 启动成功后**自动最小化仪表盘**，把前台让给目标程序（可勾选关闭）
2. 新增 **F5 全局热键**：配好参数后按 F5 启动，窗口自动最小化；  
   切到目标界面操作，再按 F5 暂停（想彻底结束就切回仪表盘点「停止鼠标」）。  
   **热键在窗口无焦点时依然生效**  
   （用 `RegisterHotKey` 系统级注册，不是网页的 keydown 监听）
3. F5 被占用时自动降级 `Ctrl+F5` → `F8`，并在界面提示实际生效的按键

### 添加自定义按键后下拉框出现重复项 —— 已修复

`initButtons()` 在重建选项时没有先清空，而它在「启动时初始化」  
和「添加自定义按键后」都会被调用，于是选项一次次累积。

**修复**：重建前 `innerHTML = ""`，并尽量保留用户当前选中项。

### 最大化按钮点了没反应 / 拖边框不能缩放 —— 已修复

**为什么最大化无效**：pywebview 的无边框窗口走 WinForms  
`FormBorderStyle = None`，实测它的窗口样式位是 `0x16010000`，里面  
**没有 `WS_THICKFRAME`**。而 Windows 判定「窗口可缩放/可最大化」  
依赖的就是这个位，缺了以后系统会直接丢弃 `SC_MAXIMIZE` 类命令——  
所以旧代码发 `WM_SYSCOMMAND` 完全没有效果，不是代码写错，是命令被丢了。

**修复**：最大化改成**自己算矩形**——取显示器工作区（自动排除任务栏），  
用 `SetWindowPos` 铺满，并记住最大化前的位置供还原。  
这条路完全不依赖窗口样式位，也不依赖 pywebview 的版本行为。  
同时把 `WS_THICKFRAME` 补回样式，窗口四周各埋一条缩放热区，  
拖动时把缩放循环交还给 Windows（因此贴边分屏、拖出屏幕这些系统行为都保留）。

**为什么不用系统自带的 `SW_MAXIMIZE`**：那条路要求 `WS_MAXIMIZEBOX` 生效，  
而无边框窗口这条路被堵死了。既然要自己动手算，  
不如一次算到底，两种情况行为一致。

### 前台程序卡死时本程序也退不出来 —— 已修复

`SendInput` 是**同步阻塞**的：事件要排进目标窗口的输入队列，  
系统会等目标线程处理完才返回。**前台程序一旦未响应**，  
这个调用就永远不返回。

而「释放所有按键」恰好要走 `SendInput`，且它出现在停止和关闭这两条路上——  
也就是**目标程序一卡死，本程序就关不掉，而此时键还按着**，  
正是最需要成功的一次释放。

**修复**：释放动作放进守护线程，主流程最多等 1.5 秒就继续；  
真的没发完时会**如实提示**「前台程序无响应，按键可能没松开」，  
而不是骗你说「已停止」。

### 滚动条风格与整体不一致 —— 已修复

原来完全没有 `::-webkit-scrollbar` 样式，WebView2 用的是默认亮灰色滚动条，  
是整个深色界面里唯一的亮色元素。现已改成与面板同一套切角风格的青色发光条。

### exe 被占用、进程杀不掉（拒绝访问）—— 原因与不重启的解决办法

**现象**：覆盖 `爪Pro.exe` 提示被占用；`taskkill /F`、PowerShell  
`Stop-Process -Force`、甚至任务管理器都返回**拒绝访问**，最后只能重启。

**两个原因叠加**：

1. **权限不对等（主因）** —— 本工具要向游戏注入输入，而游戏常以管理员  
   权限运行（本机原神已确认如此），所以你多半是**右键 → 以管理员身份运行**  
   启动的。此时该进程是**提权进程**：  
   **非提权的任务管理器 / CMD / PowerShell 无权终止提权进程**，  
   Windows 一律返回"拒绝访问"。  
   注意：`Ctrl+Shift+Esc` 打开的任务管理器默认**不是**管理员权限。
2. **窗口卡死导致"看起来像系统进程占用"** —— 窗口超过 5 秒不响应消息时，  
   Windows 会让 `dwm.exe`（桌面窗口管理器）接管出一个**幽灵窗口**。  
   于是任务管理器里那条"连点 / 锁定器(未响应)"的**进程名显示成 dwm**。  
   dwm 是系统关键进程，本来就杀不掉——  
   **它是症状，不是病因**，真正僵住的是我们自己的进程。

**不重启的解决办法**（按此顺序尝试）：

```powershell
# 1) 关键：必须用**管理员身份**打开 PowerShell
#    开始菜单 → 输入 powershell → 右键 → 以管理员身份运行

# 2) 按进程名杀（/T 连子进程一起杀，对付 PyInstaller 的父子双进程）
taskkill /F /IM "爪Pro.exe" /T

# 3) 还不行就按 PID 杀（先用 tasklist 查 PID）
tasklist /FI "IMAGENAME eq 爪Pro.exe"
taskkill /F /PID <PID> /T

# 4) PowerShell 等价写法
Get-Process 爪Pro -ErrorAction SilentlyContinue | Stop-Process -Force
```

> **为什么会有两个进程**：单文件 exe 由 PyInstaller 打包，启动时会先跑一个  
> bootloader 父进程，再拉起真正的子进程，两者都持有 exe 文件的句柄。  
> 所以只杀掉其中一个，文件锁依然在——**必须按镜像名或用 `/T` 杀进程树**。
>
> 但**另一种"两个进程"是重复双击造成的**：程序已经开着，你又双击了一次。  
> 两个实例会抢同一批系统热键（后注册的失败，界面却可能还显示"已绑定"），  
> 而且两个进程都握着 exe 句柄，更难清理。  
> v7 起加了**单实例保护**：再双击时不会起第二个进程，  
> 而是把已经开着那个窗口顶到前台。

**从源头避免**（已修）：

- 关闭时若清理卡住，8 秒后由看门狗直接结束进程，不再留僵尸进程占着 exe；
- 释放按键走守护线程 + 超时，不会把界面线程拖死。

**以后图省事**：不注入游戏、只在普通窗口用的话，直接双击运行即可，  
不必用管理员身份——这样就算卡住，普通任务管理器也能正常杀掉。

### ⭐ 触发方式（先看这个）

**连点必须发生在目标程序上**——注入事件只发给「当前前台窗口」。

程序提供**两类触发方式，可以同时绑定，按哪个都行**：

| 类型      | 默认触发键                                   | 作用                          | 占用风险            |
| ------- | --------------------------------------- | --------------------------- | --------------- |
| 系统热键    | `F5`（可改）                                | 鼠标连点 / 长按 **启动 ↔ 停止**       | ⚠ 会被游戏、远程控制软件抢走 |

1. 在仪表盘里设好参数（按键、次数、CPS 等）
2. 按 **鼠标中键**（或 `F5`）→ 仪表盘自动最小化，让位给目标程序
3. 切到你要操作的游戏 / 软件，正常操作
4. 再按一次**鼠标中键**暂停，再按一次继续（想彻底结束就切回仪表盘点「停止鼠标」）

#### 绑定触发键：按一下就绑（不用下拉选）

触发方式区提供两条绑定入口，**都是「按一下就绑」**，不需要从下拉列表里挑：

**① 绑鼠标键**

1. 先在右边选作用对象：`→启停鼠标连点` 或 `→ 启停键盘锁定`
2. 点 **「按下要绑的键」**，按钮开始呼吸闪烁
3. **直接按下你想用的鼠标键**（中键，或任意侧键 G1~G8）
4. 自动绑定完成，界面显示绑定的键名

**② 改系统热键**

1. 选作用对象：`→ 鼠标连点热键` 或 `→ 键盘锁定热键`
2. 点 **「按一下录入」**
3. **按下你想要的组合键**，比如 `Ctrl+Alt+M`、`F7`、`Ctrl+Shift+空格`
4. 自动改绑。想还原默认就点「恢复默认」

支持的热键写法：字母 A~~Z、数字 0~~9、F1~~F24，  
以及 Space / Tab / Enter / Esc / Home / End / PageUp / PageDown /  
方向键 / 小键盘 Numpad0~~9 / Delete / Insert 等，  
可任意组合 Ctrl / Alt / Shift / Win。

> 绑定时按 `Esc` 取消。`F12` 是紧急释放键，不允许同时当触发键（会拦下并提示）。

**为什么推荐鼠标键而不是 F5**：系统热键池是共享的，游戏和远程控制软件  
（向日葵、ToDesk、RustDesk 等）会抢 `F5`/`F8`/`F9`。  
而鼠标中键在游戏里通常没有默认绑定，是一条**几乎不可能被抢占**的通道。  
程序已默认把鼠标中键绑成鼠标连点的触发键，开箱即用。

> **旧版本的绑定只能从下拉里选「鼠标中键 / G1 / G2」三项**，  
> 所以游戏鼠标上的 G3~G8 根本绑不了。现已改为按需捕获，  
> 位图里的 16 个编号全部可用（除左键/右键——绑了会导致点界面就误触发）。

#### 绑不上怎么办：先看底部自检条

触发方式板块底部有一条自检信息，实时显示监听链路状态：

| 显示项      | 含义                                                       |
| -------- | -------------------------------------------------------- |
| **监听**   | `原始输入（正常）` = 走驱动级通道，全部按键可用；`降级轮询` = 原始输入不可用，只能识别中键/G1/G2 |
| **消息数**  | 收到的原始输入条数。**按一下鼠标键，这个数字应当增加**                            |
| **最近按键** | 最后按下的键（中键 / G1 / G2 …）                                   |

排查口诀：

- **消息数一直是 0** → 链路没通，程序没收到任何输入（检查是否开了锁屏/UAC 安全桌面、安全软件拦截）
- **消息数在涨但绑不上** → 链路是通的，问题在绑定这一侧
- **显示「降级轮询」** → 原始输入建不起来，此时 G3 及以上绑不了，用中键或 G1/G2

> 这一条是这次修 bug 时加的：绑键失效的根因是几个十六进制常量写错，  
> 而这类错误**不抛异常、不报错**，只有靠"消息数是否增长"才能一眼看出来。

#### 生效按键：按键捕获，不是下拉

要绑的键有 104 个，加上 Ctrl/Alt/Shift 组合是几百种，  
做成下拉反而更难点——所以这里用**按键捕获**：

1. 点 **「按一下录入」**（按钮开始呼吸闪烁）
2. **直接按下你在游戏里用的键**——单个键（`w`）或带修饰键的组合（`Ctrl+W`）都行
3. 想录多个键就重复点一次「按一下录入」，每录一个显示成一个**筹码**
4. 点筹码上的 **×** 单独删掉那一个；「删除末键」去掉最后一个

手打仍然保留（输入框就在旁边），改完文本筹码会自动同步。  
绑定时按 `Esc` 取消。

#### 两种锁定行为的区别

| 行为       | 注入方式                   | 目标程序看到什么    | 适合            |
| -------- | ---------------------- | ----------- | ------------- |
| **一直按着** | 按频率重复注入按下，**永不注入抬起**   | 键一直没松开      | 游戏持续移动（角色一直跑） |
| **反复点击** | 每组注入「按下 → 等 20ms → 抬起」 | 一次完整点击，重复多次 | 刷怪/连点类交互      |

**「按下时长」为什么关键**：目标程序通常要求「按下持续足够久」才判定为一次有效点击。  
设成 0（按下抬起零间隔）会被当成抖动直接忽略，表现为「选了反复点击但完全没反应」。  
一般 **15~40 毫秒**最稳，不要调到 0。

### 键盘锁定怎么用

1. 设好参数 → 点「① 就绪」（或直接按 F6）
2. 按 **F6** 启动监听（或点了「① 就绪」后按 F6；仪表盘自动让位）
3. **长按**目标键（如 W）超过设定秒数 → 进入锁定，状态栏显示「已锁定」
4. 松开手，锁定依然生效
5. **再按一次同一个键** → 解除锁定
6. 按 **F6** 暂停/恢复（**暂停会松开按键并解除锁定**，恢复后重新长按目标键即可再锁）；点「停止」才真正结束并回到未就绪
7. 任何异常按 **F12** 强制释放全部按键

### exe 双击打不开 / 被系统拦截 —— 智能应用控制（Smart App Control）

**本机实测状态**：Windows 10 Pro 25H2（Build 26200），  
智能应用控制处于 **Enforce（强制）模式** ——  
注册表 `VerifiedAndReputablePolicyState = 1`，  
之前是 `SAC_PreviousState = 2`（评估模式），主动开启的。

**它拦你的原因**：SAC 只放行「已验证且声誉良好」的应用。  
PyInstaller 打包出来的 exe **没有代码签名、也没有下载量声誉**，  
所以在它眼里就是来路不明的程序，直接拦住。

#### 第一步：先分清到底是谁拦的

三种拦截来源的提示语不一样：

| 拦截者         | 典型提示                      | 是否可单独放行          |
| ----------- | ------------------------- | ---------------- |
| **智能应用控制**  | 「此应用已被你的组织阻止」/ 无提示，进程直接不起 | ❌ 无白名单机制，只能关掉    |
| SmartScreen | 「Windows 已保护你的电脑」         | ✅ 点「更多信息 → 仍要运行」 |
| Defender    | 检测到威胁                     | ✅ 加排除项           |

**最快的判断方法**：看启动日志有没有生成。

```
%LOCALAPPDATA%\MouseAutoClicker\logs\launch.log
```

- **日志没生成** → 进程压根没跑起来 → 是**系统层面**拦的  
  （智能应用控制 / SmartScreen / Defender），**不是程序的问题**
- **日志生成了** → 程序跑起来了，问题在代码或环境 → 直接看日志内容

> 这正是启动日志最有用的地方：它能把「程序坏了」和「系统不放行」  
> 一刀切开。以前这两类都表现为「打不开」，只能靠猜。

#### 第二步：不想改系统设置 → 用源码方式启动

交付目录里有个 **`启动-源码方式.bat`**，双击它就行。

它直接调 Python 跑源码，不经过那个没签名的 exe。  
`python.exe` 是正常安装的，通常不在 SAC 拦截范围内。

> 如果 bat 也被拦，说明 SAC 连 python.exe 都不放行，  
> 那就只能走下一步关掉它。

#### 第三步：关掉智能应用控制

**先说清楚代价**：这个开关**单向不可逆**。  
关掉之后，除非重装系统，**再也开不回来了**（这是微软的设计，  
为了防止恶意软件临时关掉它再打开）。

在**管理员身份**的 PowerShell 里执行：

```powershell
# 1) 改成 0 = Off
reg add "HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy" `
    /v VerifiedAndReputablePolicyState /t REG_DWORD /d 0 /f

# 2) 确认改成功了（应显示 0）
reg query "HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy" /v VerifiedAndReputablePolicyState
```

然后**必须重启**才生效（这是内核级检查，改完注册表不会立即生效）。

> Windows 安全中心 → 应用和浏览器控制 → 智能应用控制  
> 这条路在 Enforce 模式下「关」按钮是灰的，点不动，  
> 所以必须走注册表。

### 启动日志（排查问题用）

日志位置：

```
%LOCALAPPDATA%\MouseAutoClicker\logs\launch.log
```

每次启动都会追加一段，内容包含：

- 启动时间、可执行文件路径、工作目录、运行方式（打包 exe / 源码）
- Python 版本、系统版本、命令行参数
- 鼠标原始输入监听的注册结果（`registered` / `messages` / `hint`）
- 系统热键与鼠标键触发器的注册结果
- 界面文件是否成功写出、窗口是否成功创建
- **任何一步出错时的完整堆栈**

超过 2MB 会自动只保留最后 400 行，不会无限膨胀。

**遇到问题时的标准动作**：把这个文件直接发出来，  
比复述「打不开 / 没反应 / 闪退」有效得多。

### 参数会自动记住

上次设的按键、CPS、次数、时长、触发键等全部存在 **exe 同目录的 `ui_settings.json`**，  
关掉重开直接沿用，不用重调一遍。

这个文件和命令行版用的 `config.json` 是分开的两个文件：  
前者的字段只服务界面，后者只服务命令行，混在一起迟早对不上。

想恢复出厂设置，直接删掉 `ui_settings.json` 即可。

### 注意事项

- 绕过反作弊（驱动级输入、进程内存修改）通常违反游戏用户协议，  
  本程序不提供，也不建议使用。
- 已知可用场景：记事本、浏览器地址栏、Office、传统 Win32 程序。
- 高权限程序（如以管理员运行的游戏）需要本工具也以管理员身份运行，  
  否则注入会被 Windows 拦掉。
