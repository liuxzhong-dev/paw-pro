# 扩展开发指南 —— 以后加功能（鼠标录制 / 新动作 / 新区）照这个来

> 这份文档回答一个问题：**以后想加一个新模块，要动哪些文件、按什么顺序动。**
> 写于 2026-10-16（v14 收尾轮）。加功能前先读这篇，能少踩八成坑。

---

## 一、架构总览：四层，两个界面

| 层 | 文件 | 职责 | 加功能时动不动 |
|---|---|---|---|
| 注入层 | `core/inputs.py` | SendInput 封装（鼠标/键盘/滚轮） | **几乎不动**。真缺能力才加，且必须两个界面共用 |
| 插件层 | `plugins/*.py` + `core/engine.py` | 动作逻辑（连点/拖拽/宏…） | **主要战场**。新动作写在这里 |
| 界面层（甲） | `app.py`（tkinter） | 插件外壳：按 FIELD 声明**自动画表单** | 加插件不用动；加新型控件才动 |
| 界面层（乙） | `dashboard.py`（pywebview） | 双区仪表盘（鼠标区/键盘区） | 加「区」才动，改动量最大 |
| 辅助层 | `core/hotkey.py` `core/button_trigger.py` `core/toast.py` `core/pausectl.py` `core/dpi.py` | 热键、鼠标键触发、通知、暂停、DPI | 按需挂接 |

**两个界面的分工（关键认知）**：

- `app.py` 是**插件化外壳**——新增一个 `plugins/xxx.py`，界面自动多一个页签，
  表单按 `FIELD` 声明自动生成，**一行界面代码都不用改**。这是「最容易的扩展路径」。
- `dashboard.py` 是**专用仪表盘**——鼠标区/键盘区两个卡片是写死的，
  **不走 Registry**（`_make_mouse_plugin()` 自己造插件）。
  在仪表盘里加新区 = 改 HTML + Api + State + 触发器，工作量约为插件路径的 5 倍。

> **选路原则**：新功能优先走 `plugins/` 路径（app.py 自动有界面）；
> 只有当功能必须常驻仪表盘双区（要和热键/暂停/通知体系深度整合）时，
> 才动 dashboard.py。**鼠标录制的回放器走插件路径，录制器走 core/ 路径。**

## 二、一个插件的完整长相（照抄这个结构）

```python
# plugins/my_feature.py
import sys, os
_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
if _ROOT not in sys.path:
    sys.path.insert(0, _ROOT)

from core.engine import Plugin, Registry

class MyFeature(Plugin):
    name = "my_feature"          # 唯一英文标识，配置存储用它
    title = "我的功能"            # 界面显示名
    description = "一句话说明"

    FIELD = [                     # 界面控件声明，app.py 读它自动画表单
        {"key": "speed", "label": "速度", "type": "int",
         "default": 10, "min": 1, "max": 100},
        {"key": "loop", "label": "循环", "type": "bool", "default": True},
        {"key": "text", "label": "备注", "type": "text", "default": ""},
    ]

    def on_start(self, ctx):      # 钩子：开始前一次。返回 False 可阻止启动
        return True

    def run(self, ctx):           # 钩子：主循环。ctx 见下
        while not ctx.should_stop():          # 注意是方法，不是属性
            # …… 干活 ……
            ctx.clicked += 1                  # 计数必须加，否则界面永远显示 0
            if not ctx.wait(1.0 / 10):        # 可中断等待；False = 已停止
                break                          # 只有 False 才能 break
        return ctx.clicked

    def on_stop(self, ctx):       # 钩子：停止后一次
        pass

Registry.register(MyFeature())   # 必须调，不注册 = 不存在
```

`ctx` 提供：`should_stop()` / `elapsed()` / `clicked` / `tick_count` /
`options`（界面填的值）/ `state`（插件自己的持久 dict）/ `wait(秒)` /
`base_interval()` / `cursor_position()`。**暂停能力白送**——`ctx.wait()`
开头有分区门闩，插件不用管暂停。

**三个已踩过的坑（代码注释里也有）**：

1. `ctx.should_stop()` / `base_interval()` / `elapsed()` 是**方法**，
   当属性用会拿到 bound method，while 永真且循环体一次不执行。
2. `ClickContext(duration=0.6)` 会被 `int()` 截断成 0（=不限时）。
   要小数时长自己在插件里计时（参考 `dashboard._make_mouse_plugin`）。
3. `clicked` 和 `tick_count` 都要加：界面/日志读 `clicked`，
   次数上限读 `tick_count`。只加一个 = 显示 0 次 或 永远停不下来。

## 三、完整示例：加「鼠标录制」模块

这是主人点名的下一个功能。拆成三块，**每块都能独立上线**。

### 3.1 录制器 —— 挂在已有的原始输入监听上（不用造轮子）

`dashboard.py` 的 `start_mouse_listener()` 已经有一个 Raw Input
（WM_INPUT）后台线程，`_on_raw_mouse(mouse)` 每条事件都会过。
它已经做了两件对录制至关重要的事：

- **过滤自己注入的事件**（`ulExtraInformation == MARK_INJECTED` 直接 return）
  —— 录制回放时不会把回放动作又录进去，天然防回环
- 边沿检测（按住不放只触发一次）

录制要做的只是**在旁边记一笔**：

```python
# core/recorder.py（新建）
"""鼠标录制：把真实鼠标操作按时间轴记成 JSON。"""
import json, time

_recording = []
_t0 = 0.0

def start():
    global _recording, _t0
    _recording = []
    _t0 = time.time()

def feed(mouse):
    """在 _on_raw_mouse 里调用（只录真实输入，注入的已被上游过滤）。"""
    # mouse.usButtonFlags / mouse.lLastX / mouse.lLastY / usButtonData
    # 参照现有 RI_MOUSE_* 常量解析，事件类型：move / down / up / wheel
    _recording.append({"t": round((time.time() - _t0) * 1000), ...})

def stop(path):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(_recording, f, ensure_ascii=False)
```

**挂接点只有一个**：`_on_raw_mouse()` 开头加一行
`if recorder.is_recording(): recorder.feed(mouse)`。
（注意：Raw Input 默认只报按键，移动事件要确认 RID 配置里
`usUsagePage=1, usUsage=2` 且别过滤 move——现有配置已经收 move，
`lLastX/lLastY` 就在结构体里。）

### 3.2 回放器 —— 直接复用宏插件，零新代码

录制格式**设计成宏语法的超集**，回放就不用写第二套引擎：

| 录制事件 | 转成宏语法 |
|---|---|
| 移动到 (x,y) | `move@x,y` |
| 按下左键 | `click@x,y` |
| 两次事件间隔 350ms | `wait@350` |

即：录制文件存 JSON（人可读、可编辑），点「导出为宏」时转成
`plugins/macro.py` 认识的 `steps` 字符串。**回放 = 现有宏插件，
一分钱引擎代码不写。**

### 3.3 界面 —— 两条路选一条

| 方案 | 做法 | 工作量 | 适合 |
|---|---|---|---|
| A（推荐先做） | 回放走宏插件，app.py 自动有页签；录制做成一个小按钮 + 「导出为宏」 | 小 | 快速可用 |
| B（完整体验） | 在 dashboard.py 加第三个「录制区」卡片 | 大（见下） | 要常驻仪表盘时 |

方案 B 要动的地方（按顺序）：

1. `dashboard.py` 的 HTML 常量 —— 加卡片 DOM + CSS
2. `State` 类 —— 加 `rec_running` / `rec_armed` 等字段
3. `Api` 类 —— 加 `arm_recorder` / `toggle_recorder` / `stop_recorder`
4. 触发器 —— 想用热键就接 `core/hotkey.py` / `core/button_trigger.py`
5. 通知 —— 调 `core/toast.py` 的 `show_custom(文案, kind)`
6. **回嵌 `ui/dashboard.html` 并跑 round-trip 校验**（见第四节，这条翻过车）

## 四、三条闸门（缺一条就可能「源码改了、exe 没改」）

| 闸门 | 守什么 | 怎么做 |
|---|---|---|
| ① UI 双源同步 | `dashboard.py` 的 `HTML` 常量才是打包源头；`ui/dashboard.html` 是启动时被覆盖写的**产物** | 改完界面立刻回嵌，断言：无三引号、不以反斜杠结尾、回读逐字节一致。`verify_two_stage.py::test_embedded_html_in_sync` 常驻防回归 |
| ② PyInstaller 字面量 | exe 里没有 .py 文件，靠 importlib 按**模块名**导入。动态扫目录在打包后失效（源码能跑、exe 里插件静默消失） | 新插件必须加进 `plugins/__init__.py` 的 `BUILTIN_MODULES` 字面量列表 |
| ③ exe 端到端 | 时间戳只能证明「这轮打的」，证明不了「打进去的是新代码」 | 构建脚本自动跑 `_verify_exe_html.py`：从 exe 刨出内嵌 HTML 比 md5 |

> 2026-10-16 v12 事故就是只守了截图：回归全绿、截图正常，exe 里是旧界面
> ——因为截图截的是没进 exe 的那份。**三条一起才闭环。**

## 五、零打包扩展：`plugins_ext/`

不想重新打包就能加功能，走外部插件：

1. 在 exe 同级建 `plugins_ext/` 目录（`交付/plugins_ext/` 已预留，空的）
2. 丢一个 `.py` 文件进去，内容就是第二节的插件结构
   （`from core.engine import Plugin, Registry` + `Registry.register(...)`）
3. 重启程序即生效——`load_external()` 按文件路径动态导入，
   只影响 `app.py` / `cli.py`（**dashboard 不加载外部插件**）

外部插件是真实磁盘文件，不受 PyInstaller 影响，所以**不需要**加进
`BUILTIN_MODULES`。文件名别以 `_` 开头（加载器会跳过）。

## 六、约定（照做的理由）

| 约定 | 理由 |
|---|---|
| 插件 `name` 用英文小蛇形 | 配置存储的 key，中文会惹兼容麻烦 |
| 新能力先问「inputs.py 有没有」 | 两个界面共用一份注入层，别各写一半 |
| 计数器必须加 `clicked` | 界面/日志/结束统计全读它；漏加 = 显示 0 次，排障全被带偏 |
| 文案里的键名用 `_hotkey_label()` / `_trigger_label()` | 热键会降级（本机 F5/F6 全被占，实际是 F8/F9/ScrollLock），写死常量 = 提示撒谎 |
| 加功能必须带 `verify_*.py` | 打桩绿灯不算验证（对「目标窗口里能不能动」覆盖率 0），但它是回归网 |
| 改完数值 grep 旧值归零再交付 | 「声称已修复」≠「已验证修复」 |
